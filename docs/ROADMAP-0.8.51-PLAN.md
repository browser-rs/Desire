# v0.8.51 规划稿 —— 工具面 3.0：283 个工具要「找得到、串得起来、看得见表现」

> 基线：v0.8.50（2026-11-11，590）。工具数量已经不是短板——Agent 工具
> **283 个**、工具箱 **81 个**。短板是**工具面的可用性**：系统提示词每次请求
> 都要塞一份全量工具索引（每行一句话），弱模型挑不准；没有工具搜索；没有
> 组合调用；单个工具吐大结果会吃掉上下文；哪个工具老失败也没人统计。
> 本版不堆数量，只把工具面做成"能被找到、能被串起来、能被度量"。

## 为什么是它

- 283 × 一行摘要 ≈ 20KB+ 系统提示词，**每回合都付**；小模型还容易被淹没。
- 常用组合（开标签→抓正文→存摘录）只能靠模型一步步串，回合数多、失败点散。
- 长输出（`executeJS`/`readFile`/页面正文）没有统一预算，一次就能把上下文顶爆。
- 轨迹里已有每工具耗时/失败标记，但**没有按工具聚合的视图**——漂移的工具
  （选择器改版、站点反爬）只能靠用户报障才发现。

## 旗舰（P0）：工具面 3.0

### 1. 按需工具目录（progressive disclosure）

- `<tools>` 索引从"全量一行一个"改为**按域分组**：浏览器/标签/页面/内容/媒体/
  文档/系统/Jobs/记忆/技能/MCP/研究…，每组一行（组名 + 工具数 + 3-5 个代表 +
  "listTools 展开"）。
- 新增元工具 **`listTools {query?, group?, limit?}`**：返回匹配工具的完整定义
  （名称/一句描述/参数名与类型）；命中过多时回"收窄关键词/指定 group"。
- 保留"何时展开"的规则（不确定工具名/参数时先 listTools）。
- **度量**：假 OpenAI 端点抓请求体，`<tools>` 段字符数下降 **≥60%**，`tools`
  数组仍全量（function-calling 不缩水，避免模型调用未下发工具）。

### 2. 工具链 `runToolChain`

- 入参：`steps: [{tool, args}]`（≤10 步）、`onError: stop|continue`、
  `background?: bool`。
- 变量：`$prev`（上一步结果文本）、`$prev.field`（上一步 JSON 的字段）、
  `$1..$n`（第 n 步结果）；替换发生在**参数字符串**里（`"$prev"` 整值或
  `"prefix $prev"` 混排）。
- 执行：严格顺序（副作用步骤绝不并行——只读批的教训）；每步结果摘要进返回；
  失败按 onError 决定停或继续，最终列出成功/失败步。
- `background: true` → 交给 Jobs（长链/批量场景），完成备注 + 通知。
- 验收：`newTab → getPageSnapshot` 两步链一次调用完成；`$prev` 正确注入；
  第二步失败时 stop 与 continue 的返回符合语义。

### 3. 工具结果预算（防上下文爆炸）

- 统一截断：单工具结果默认上限 **24k 字符**，超出追加
  `[…truncated N chars — use limit/offset or a narrower query]`。
- 长输出工具提供分页/范围：`readFile {offset,limit}`、`executeJS` 结果已字符串化、
  `researchBrief status` 的简报正文可 `sections: true` 只取目录。
- 度量：单回合上下文峰值下降；截断标记必须显式存在（不静默丢内容）。

### 4. 工具统计（看得见表现）

- 从轨迹/消息派生（口径与 `AgentTrace` 一致：只认 `Error:` 与"拒绝执行"为失败），
  按工具聚合：调用数、失败率、平均/P95 耗时、最近一次失败时间与摘要。
- `GET /agent/tool-stats` + Agent 侧栏「工具」页（Top 失败、最慢、最近新增）。
- 用途：优先修漂移工具；新增工具后观察真实使用率。

## 四主题常规（各一件）

### 5. 浏览器基础：标签页批量

- 「复制全部标签链接」为 Markdown 列表 / 纯文本（当前不可用）；
- 右键「关闭其他标签 / 关闭左侧 / 关闭右侧」（Chrome 惯例）；
- 桥命令同名动作，便于脚本。

### 6. Agent 基础：工具超时分级与取消传播

- 每个工具声明超时档（默认 60s；命令/下载/导出走 job 模式不受此限）；
- 超时返回 `Error: timed out after Ns — use a job-based tool for long work`；
- 用户取消回合 → 正在跑的工具收到取消并立即收尾（不把僵尸任务留在后台）。

### 7. 融合：工具结果一键分发

- Agent 消息里的工具结果卡 / 工具箱结果页统一动作：**发到白板**（结构化块）、
  **存为摘录**（带来源）、**复制 Markdown**；
- 复用现有 `WhiteboardStore` / `ExcerptStore`，不新建存储。

### 8. 替人干活：批量跑纯工具

- 对文件批量执行纯工具：**批量正则替换**、**批量哈希**、**批量编码转换**，
  走 Jobs 台账（逐文件结果、失败可见、可取消）；
- 入口：工具箱对应工具的「批量」页签 + Agent 工具 + 桥。

## 贯穿

- **可发现性**：`listTools` 结果带 group/示例；工具统计页；`/help` 提到研究/工具链；
  What's New 一条"工具找得到也串得起来"。
- **可靠性**：结果预算/超时/取消三条一起落地（都在工具执行层收口，不许各工具自写）。
- **i18n**：新文案三语在提交时补齐（CLI 构建不抽键）。
- **不做**：继续堆工具数量（先解决发现与质量）、工具市场、第三方工具热加载
  （插件系统已有）、重写 function-calling 协议、MCP 工具自动信任。

## 批次

1. **批 1（P0）**：`listTools` + 分组索引 + 提示词瘦身与度量（假端点抓请求体）。
2. **批 2（P0）**：`runToolChain` + 变量/失败语义 + 后台 Jobs。
3. **批 3（P0/P1）**：结果预算 + 超时/取消 + 工具统计端点/页面。
4. **批 4（收口）**：四主题常规 + i18n/WhatsNew + 套件 + 发版闸门。

## 验收

- 批 1：`<tools>` 段字符数降 ≥60%、tools 数组仍全量；agent-eval 能力用例仍过；
  fixture 里模型通过 `listTools` 找到并调用目标工具。
- 批 2：两步链一次调用成功；`$prev`/`$1` 替换正确；stop/continue 语义正确；
  后台链进 Jobs 且完成通知到达。
- 批 3：超限结果截断且带显式标记；超时工具返回 `Error: timed out`；取消 2s 内收尾；
  `tool-stats` 的调用数与轨迹逐条一致。
- 批 4：复制链接清单格式正确（Markdown 列表/纯文本）；工具结果进白板与摘录；
  批量纯工具产物与 Jobs 台账逐项对齐。
