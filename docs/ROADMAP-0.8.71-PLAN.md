# v0.8.71 规划稿（2026-11-21）—— 上下文重构：分层压缩管线（Agent 基础旗舰）

> **背景（0.8.70 发版后真实事故）**：用户 GLM-5.3-Flash（窗口 1M tokens）遭遇
> 三连症状——上下文额度显示极少、自动压缩频繁触发、模型"失忆"（要回头看
> 之前的会话才能理解）。根因链：默认窗口表把 glm 猜成 32k（实际 1M）×
> 校准比率贴下限 1.5 → 生效预算 19k 字符（160k 的 12%）→ 每轮触发压缩 →
> 机械摘要把细节裁光。**表层修了（档案显式设 1M 已生效），但整个上下文
> 管线的设计必须重构**——本版为 Agent 基础旗舰。
>
> **设计原则（2026 年成熟智能体共识，已调研）**：
> 1. **分层递进压缩（tiered compaction）**：便宜操作先行，每层后重新计量，
>    够用即停——不一刀切。
> 2. **微压缩优先**：工具输出是上下文最大膨胀源（单条可达 47KB）——确定性
>    规则清除/截断旧工具输出（无 LLM 调用、零成本），是第一层。
> 3. **LLM 语义摘要是最后手段**：前面的层不够才用，且摘要必须保留语义
>    （目标/决策/路径/数据/未完成），不是动作清单。
> 4. **锚定信息钉住**：用户目标与明确约束永不裁剪（重复有损压缩会导致
>    行为退化——治理衰减）。
> 5. **阈值从模型推导**：窗口 − 输出预留 = 预算；绝不硬编码。
> 6. **压缩时机 = LLM 调用之前**；能后台做的不阻塞前台。
> 7. **用户控制**：压缩可带自定义保留指令；占用可查看（真值）。
>
> **规划前核实（2026-11-21）**：模型清单拉取已升级为 `ModelEntry`（带
> provider 自报窗口，多字段名兼容），档案新增 `modelContextWindows` 映射
> （本日已落）；档案显式 `contextWindowTokens` 已设 1M 并生效（生效预算
> 600k chars）。**遗留 = 猜表仍在、消费侧仍读猜值、无微压缩、摘要是机械
> 清单**——全部在本版重构。

## 旗舰：上下文管理 2.0（Agent 基础）

### A. 窗口真值层（批 1）
- **删 `defaultWindowTokens` per-name 猜表**（glm→32k 等全部移除）。
- 消费优先级：**档案显式 `contextWindowTokens`**（用户设置，UI 已有输入框）
  > **`modelContextWindows[model]`**（provider /models 自报，本日已加）
  > **溢出错误自动学习**（isContextOverflowError 命中时解析错误文本中的
  > 真实窗口数字，写入 `modelContextWindows`——用户没显式设过才写）
  > **都没有 = 未知 → 不做窗口换算，回退字符预算 160k**（0.8.59 前的
  > 安全默认——"猜窗口"从预算计算里彻底移除）。
- 所有消费点（calibratedBudgetChars / healthSummary / 设置页显示）改读
  同一解析链；未知时 UI 标注"窗口未知，使用默认字符预算"。

### B. 用量真值层（批 1）
- **占用% = 服务端自报 prompt_tokens ÷ 窗口**（每回合 usage chunk 已捕获，
  真值直读——不再用 chars ÷ chars 预算）。服务端不报 usage 时回退字符
  估算并标注。
- 面板状态行显示"tokens / 窗口"双数字（对齐模型视角）。

### C. 分层递进压缩管线（批 2-3，核心重做）
触发时机：**构建请求之前**（buildRequestMessages 内，现有钩子点）；
压缩决策按生效 token 用量分层递进，**每层后重新计量，够用即停**：

- **Tier 1 微压缩（确定性规则，无 LLM）**：从最旧的工具结果开始，把超过
  保留窗（最近 2 轮的完整输出）的工具输出替换为占位行
  `[工具结果已收起（N KB）——需要时用 recallConversation 检索]`。
  每替换一批重新计量。工具输出是最大膨胀源（单条 47KB），这一层
  通常就够了。**结果正文进轨迹归档可检索**（recallConversation 已有）。
- **Tier 2 LLM 语义摘要**：Tier 1 不够 → 被裁的**用户轮次+助手回答**
  交给旁路便宜模型生成语义摘要（提示词明确要求保留：用户目标、关键
  决策、发现的路径/URL/数据、未完成事项），替换原文。**用户目标与
  明确约束钉住不裁**（治理衰减防护）。失败回退机械摘要（不阻塞回合）。
- **Tier 3 紧急裁剪**：Tier 2 后仍超 → 更激进裁剪（摘要区合并、只留
  最近 1 轮全文）+ 明确告知用户。
- 被裁原文**全部先归档**（conversation-<id>.archive 既有机制）——
  数据永不丢。

### D. 用户控制（批 3）
- `/compact [保留指令]`：手动触发，支持自定义保留指令（"保留所有路径"）
  —— 指令并入摘要提示词。
- `/context`（或面板状态行点击）：查看各区占用（锚定/摘要/全文/系统）
  + 窗口来源标注（显式/provider/未知）。
- 压缩发生时状态行可见（"已收起 N 轮工具输出（归档可查）"）。

## 风险

- **Tier 1 截断的召回体验**：工具结果收起后模型"忘了"某数据 → 已有
  recallConversation 兜底（摘要占位行里指路）；Agent 的系统提示词要加
  一条"被收起的结果用 recallConversation 检索"的指引。
- **语义摘要质量**：旁路便宜模型摘要可能丢细节——归档原文兜底 +
  摘要可重做（/compact 带指令）。
- **prompt_cache 效应**：改写历史轮次会使服务端 prompt 缓存失效（成本
  上升）——Tier 1 只动"最旧且已出保留窗"的输出，替换一次后稳定；
  观察用量成本变化（成本面板有真值）。
- **治理衰减**：锚定区 + 摘要质量检查（轨迹可查）+ 归档不丢三重防护。
