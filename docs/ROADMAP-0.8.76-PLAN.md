# v0.8.76 规划稿（2026-11-24）—— 做过的不重做：重复任务的熟练度（Agent 基础旗舰）

> **背景**：0.8.71–0.75 五连把智能体的上下文、记忆、技能、学习、仪表盘都补齐了，
> 但全部是"从代码出发"找缺口规划的。本版换方法：**先看真实使用数据，再定主题**。
> 数据来自本机应用自己的落盘（会话轨迹、批量下载索引、系统诊断），只做聚合。
>
> **数据说了什么**（近十天，剔除了开发与测试实例的记录）：
> - 智能体真实使用 = 6 个会话、30 条消息、99 次模型请求、**1113 万输入 token**、
>   89 次工具调用，**全部围绕同一件事：把一个论坛列表页的视频批量下载下来**。
> - 同一句批量下载指令，一天之内被重复下达 **8 次**。
> - 19 个技能里 18 个是出厂示例，**只有 1 个是真实使用产生的**。
> - 定时任务 0 个、电子书 0 本、适配器 0 个、hooks 0 个、👍/👎 0 次。
> - 三个真实会话里有两个以 **HTTP 429（额度耗尽 / 并发限流）** 结束。
>
> **用户在任务中的原话**（不含站点信息，逐字）：
> - "失败太多次了 为啥不先好好分析一下"
> - "不会总结的吗？" · "之前刚跑完过一页的啊"
> - "你在自作主张 页面有可能超过100个视频的啊"
> - "你自己写的技能 你自己修改对啊 你要修改对啊"
> - "我感觉你处理起来每一步都在犯错"
> - "为什么要反反复复看这个结果！！明明有重复的 你到底在干什么啊？"
>
> 一句话：**同一件事做八遍，每一遍都像第一次。** 这不是缺能力，是已有的能力没有
> 在这条工作流上接起来。本版只做一件事——让做过的事不再重做。

## 规划前核实（2026-11-24，代码 + 使用数据）

| 现象 | 核实结果 |
|------|---------|
| 重复指令不自动命中技能 | 指令→技能**没有任何确定性匹配**；技能索引只注入名字+描述，要不要 `useSkill` 全凭模型自觉；跨会话的程序性记忆只有技能本体 |
| 技能错了不自己改 | 用户纠正只进 correction 记忆（0.8.73）——那是"别这样做"，不是"把做法改对"；重蒸馏（0.8.73）是整体重生成且要连败 3 次才出现；**没有定点修正通道** |
| 反复查进度 | 等待机制**其实已存在**（`watchBackgroundTasks` 订阅 → 完成写备注/发通知，`mode=resume` 自动开新回合），但：① 工具说明写着"仅用户明确要求时才用 resume"；② 下载类工具回执写着 "poll via…"、"listBatchDownloads reports progress"——**回执在教模型轮询**；③ **短 id bug**：下载工具回执给的是 8 位短 id，订阅工具只认完整 UUID，传短 id 即 "job ids are invalid"（真实会话里它被调 1 次、失败 1 次，进度查询 13 次） |
| 原地打转 | 回合内**没有**重复观察/无推进检测（只有迭代上限） |
| 每次请求 11 万 token | 请求里工具定义占八成多字符（0.8.74 计量）；这条工作流全程只用了 **18 个工具**，而每次请求全量发送 295 个 |
| 诊断噪声（另一条线） | 安装版 34 次"主线程停滞"记录，可判定的 33 次里 **32 次落在系统睡眠的 DarkWake 窗口（唤醒后 0–2 秒）**，1 次在完整唤醒后 1 秒——**零次真实卡顿**。根因：心跳年龄用墙钟计算，机器睡眠时墙钟照走。后果：每次误报 fork `sample` 采样 2 秒（在系统短暂唤醒的省电窗口里）、`health/` 堆 22.6MB 采样无清理（占 Desire 目录 85%）、体检页永久显示假停滞。0.8.70 的修复只覆盖了模态弹窗一类 |
| 诊断数据混源 | 开发实例与安装版同 bundle id 共用 health/diagnostics，系统每日指标不分来源；测试还把 24 条作业、17 个监视等残留写进了真实存储 |

## 旗舰 A：重复指令直通技能

- **触发短语的三个来源**：① 新建/蒸馏时由旁路从技能描述生成；② **从使用中学习**——
  每次 `useSkill(name)` 被调用，记录触发它的那条用户消息（归一化，上限 20 条）；
  ③ 技能编辑器里手改。frontmatter 新增 `triggers:`（沿用 `vars:` 的行解析，纯逻辑进 harness）。
- **确定性匹配**：`sendMessage` 时把用户消息归一化后与触发短语比对（复用记忆去重的
  bigram 相似度口径）。**唯一命中且过阈值**才动作；多命中取最高；不过阈值保持现状。
- **预加载**：命中后合成一对与真实调用形状一致的 `assistant(useSkill)` + `tool(技能正文)`
  消息（toolCallId 配对正确），并在状态层注明"这是重复任务：已加载技能 X（第 N 次
  执行）。按技能执行，不要重新探索流程"。
- **首版收窄**：只对"历史触发样本 ≥ 2 条"的技能启用；设置开关"重复指令自动加载技能"；
  面板在用户消息下方显示"已加载技能 X（重复任务，第 N 次）"。
- 落点说明：规则**不写进用户可编辑的默认提示词**，走工具回执与独立状态层。

## 旗舰 B：纠正回写技能

- **纠正识别（确定性，零模型）**：本回合 `useSkill` 过某技能，且用户的下一条消息
  命中纠正模式（"不对/不是这样/你应该/为什么要/自作主张/你自己改/错了/重复…"中英表）。
- **补丁生成（旁路；无备用档案则跳过）**：输入 = 技能正文 + 本回合轨迹摘要 + 纠正原话；
  输出 = **定点补丁**（改哪一段 → 改成什么 + 一句理由），不重写全文。
- **落地走确认**：复用 0.8.72 候选收件箱，新增补丁类卡片（改前 → 改后，采纳/忽略）；
  采纳 = 同名覆盖 + 旧版备份（`skills/.archive/<name>-<日期>.md`）。
  **不自动写入**——技能是程序，自动改坏的代价高于多点一次；提供"纠正后自动应用补丁"
  设置项，默认关。
- 与 0.8.73 教训并存：教训管跨技能的泛化，补丁管技能本体。

**实施结果（批 4 ✅）与三处偏离**：
- 识别 = `SkillCorrectionCore.isCorrection`（中英形态表 + 短消息 ≤300 字符），加上
  "本会话近 60 条消息里加载过技能"；不要求"上一回合恰好加载"——真实轨迹里纠正是连着
  五六句来的，第一句纠正时技能已是两三个回合之前加载的。旁路输入 = 技能文件全文 +
  自加载以来的执行摘要 + 纠正原话 + 纠正之后的执行摘要。
- **备份目录改为 `<数据目录>/skill-backups/`**（不是规划里的 `skills/.archive/`）：
  技能目录被加载器重扫，桥的文件列表、导入与同步都要遍历它，备份不能待在里面。
- **不做"纠正后自动应用"开关**：收件箱已经够用，多一条自动改技能的路径只多一类风险。
  规划稿"风险"一节的对应条目同步作废。
- 补丁只能定点：`find` 在技能文件里逐字存在且唯一（空白差异容忍）、不动
  name/description、不超过全文一半、至少 2 个字符；提出时与采纳时各校验一次，采纳时
  定位不到 = 补丁作废并移出收件箱。
- 节流：同一（技能, 会话）10 分钟一次、全局每天 3 次，**调用旁路前**记账。
- **未做（如实记账）**：补丁卡只出现在技能页的收件箱里，聊天面板没有任何提示——
  用户纠正完当场看不到"已为技能生成修正建议"。面板内提示是下一步。

## 旗舰 C：等待不烧请求 + 打转护栏

- **把默认翻过来**：修短 id bug（订阅接受 8 位前缀唯一匹配）；下载/导出/转码类工具
  回执改为"已启动。结束本回合：调用 `watchBackgroundTasks(…, mode:'resume')` 订阅，
  完成后我会自动开新回合汇报。不要轮询"；`watchBackgroundTasks` 说明去掉"仅用户明确
  要求"；用户在本会话发起的长任务默认 `resume`，定时/后台发起的默认 `notify`；完成回合
  只做"读结果 → 汇报"，不做额外探索。
- **回合内打转护栏（确定性，只提醒不硬停）**：分类与阈值同 `TurnProgress`。
  ① 同一查看工具在本回合第 4 次调用 → 结果尾部追加提醒。阈值按真实轨迹定：
  "反复查看"22 次里 20 次是**换个参数再看**（再执行一个解析脚本、再查一遍目录、
  再读一片结果），一字不差的重看只有 1 次——所以按工具计，不看参数与结果；
  读大结果的切片最多 3 片，不触发。② 连续 4 个请求全是查看 → 下一请求注入一条
  备注"最近 4 步全是查看，没有推进：给出结论、执行下一步，或结束回合"。
  （原稿的"同工具同参数同结果第 3 次"是按假设写的，对真实轨迹基本空转。）

## 旗舰 D：按任务精简工具定义（实验开关，真值门控）

> 这是对 0.8.74 一项否决的**修订**。当时否决"工具动态子集"的理由是"模型只能调用已
> 声明的工具，裁剪即阉割"——理由仍成立。修订的依据是新证据（真实工作流 18 个工具
> vs 每次全量 295 个；一半额度花在发用不到的定义）加上一个不同的设计：**渐进披露 +
> 逃生口**，不是硬裁剪。

- 技能 frontmatter 可选 `tools:`；没有则推断 = 技能正文出现的工具名 ∪ 该技能历史执行
  实际调用过的工具 ∪ 常驻工具（useSkill/useTools/askUser/updatePlan/
  watchBackgroundTasks/remember/recallMemory/recallConversation/notify…）。
- 技能已加载的会话：请求只发"技能工具集"的完整 schema；**其余工具保留在系统提示的
  全量索引里**（模型知道它们存在）。
- 新增常驻元工具 `useTools(names:)`：调用后下一请求加入这些工具的完整 schema；模型
  直接调用未加载的工具 → 回执"本回合未加载——先调 useTools"。
- **自动回退**：本回合出现"调用未加载工具"或 `useTools` ≥ 2 次 → 余下请求恢复全量。
- 默认只在"直通技能加载的回合"启用（推断出的工具集 ≥ 5 个时），并受设置开关控制。
- **门控**：① 分层计量里工具定义层字符下降 ≥ 50%；② 真实网关 prompt_tokens 对照；
  ③ 直通任务成功率不降、回退路径可用；④ 190 全绿。任一不满足 → 发布时保持关闭。

**批 6 进展（2026-11-25）**：新增评估用例 E29 直通 / E30 纠正补丁 / E31 精简工具，
三者在隔离实例上全绿（36/36，两次不同实例复验）。agent-eval 加了封闭实例闸门
（三项隔离缺一不可——它会写假档案与技能文件）。发版冒烟加了本版只读探针；
What's New 文案已按本版刷新。**未做**：本地列表页端到端 fixture（>100 链接 +
详情页 + 本地 HLS，浏览器依赖，需实例在前台）与 190 全量（需机器空闲）；批 5
门控 ②③ 需要真实网关数据。

**实施结果（批 5 ✅，开关默认关）**：
- 工具集 = 技能 frontmatter `tools:`（作者写明就以作者为准，哪怕只写两个）∪ 正文
  点名的驼峰工具名 ∪ 该技能历史执行里实际用过的工具（回合收尾记账 + 一次性回填）
  ∪ 常驻工具（14 个：加载技能、useTools、沟通、计划、记忆、读转存结果、后台任务）
  ∪ 浏览器基本功（12 个：读页面、点、填、滚、按键、执行脚本、导航、切标签）。
  推断出的**特有**工具不足 5 个、或总数超过 48 个 → 不精简。
- 只在直通技能加载的回合生效，受设置开关控制。`<tools>` 索引照旧全量（0.8.51 起
  已是分组摘要），段首加一句"本请求只带了 N/总数 个工具的完整定义"。
- 回退：调用未加载的工具 → **不执行**（回执 `Error: tool 'x' is not loaded…`，
  并告知全量已恢复）；`useTools` 用到第二次 → 恢复全量。
- **门控结果**：① ✓ 工具定义 174,788 → 23,161 字符（295 → 33 个工具），降 86.7%，
  远低于 9 万的目标；③ 的确定性部分 ✓（未加载→回退、两次 useTools→回退、不偏的
  精简回合、开关关时照旧全量，含重启后的复验）；**② 与 ③ 的成功率部分没有数据**——
  需要真实网关与真实模型跑直通任务，要花用户的额度且需要用户在场，**未做**。
  ④ 190 未在隔离偏好下跑过。按门控规则，**发布时保持默认关**。
- 顺手修掉一个让批 3 跨启动失效的旧 bug（见 CHANGELOG Fixed）：技能使用记录的
  写入端与读取端编解码器不成对，每次启动被静默清空。批 5 的"历史执行用过的工具"
  与批 3 的触发样本都靠这份记录跨启动存活。
- 批 4 的缺口已补：聊天面板里有了修正建议条（当场可见、可应用/忽略）。

## 旗舰 E：诊断卫生（确定性小修）

1. **停滞监测睡眠感知**：心跳年龄改用不含睡眠时间的单调时钟；监听唤醒通知，唤醒后
   重新计时并冷却 30 秒；DarkWake 期间不报。阈值不变。
2. **假记录不再显示**：停滞记录加时钟口径字段；无字段的旧记录在体检页标为"旧版记录，
   可能为睡眠误报"并不计入健康结论。
3. **清理**：`health/` 保留最近 20 份采样与 30 天；diagnostics 同理（单个 oslog 2.7MB）。
4. **诊断分源**：停滞记录与每日指标带上构建来源（应用/开发）；体检与诊断包只统计应用
   来源。AGENTS.md 固化：自动化启动一律带 `--data-dir`。
5. **CHANGELOG 诚实更正**：0.8.70 的"停滞误报修复"只覆盖模态弹窗。
6. **测试残留**：此前套件写进真实存储的记录（作业/监视/命令规格/模板/开发实例采样/
   空壳会话）**不自动删除**——诊断页提供"测试残留"列表（逐条显示标题与时间），由用户
   勾选清理。

## 任务级度量（A/C/D 共用的验收尺）

在轨迹派生里按会话聚合：请求数、prompt tokens、纯观察请求占比、**首个有效动作前的
探索步数**、重复观察次数。批 1 先建基线，后续每批用同一把尺量。

## 四主题

- **① 浏览器基础** = 诊断卫生（旗舰 E）+ 真实使用反馈修复。
- **② Agent 基础（旗舰）** = 直通技能、纠正回写、等待不烧请求、打转护栏、按任务精简
  工具定义。
- **③ 融合** = Remote 四项真机验收（发图/Handoff/Siri/扫码）自 0.8.70 起一直欠着，
  本版不新增 Remote 工作，如实记账。
- **④ 替人干活** = 以真实的批量下载工作流作为端到端验收线。
- **贯穿**：可靠性（护栏、睡眠感知、自动回退）；可发现性（"已加载技能"标签、补丁
  卡片、测试残留列表）。

## 验收（以真实工作流为准，不以 190 为准）

搭本地 fixture：一个 >100 条链接的列表页 + 详情页 + 本地 HLS 切片，回放那句重复指令。

| 指标 | 基线（批 1 用同一套分类在 3 个真实会话 / 29 回合上测得） | 目标 |
|------|----------------|------|
| 首个有效动作前的探索步数 | 中位 1，p90 5，最大 5（19 个有动作的回合） | 第二次执行 ≤ 1 |
| 纯查看请求占比 | **35%**（99 次请求里 35 次；规划初稿的 19% 是按工具名粗估的） | ≤ 5% |
| 同一查看工具的重复查看 | 20 次 / 58 次查看 | 由护栏与订阅替代 |
| 连续 ≥4 个纯查看请求的回合 | 2 / 29 | 0（护栏命中后模型收敛） |
| 同一指令第二次执行的请求数 | — | 较首次下降 ≥ 50% |
| 每请求工具定义字符（D 开启） | 17.4 万 | ≤ 9 万 |
| 直通误触发（无关指令） | — | 0 |

新增评估用例（编号顺延）：直通、纠正补丁、护栏/订阅默认、精简工具的回退路径。
190 全量照跑（hermetic）。**如实说明**：fixture 只能验证智能体侧行为，验证不了真实
站点的登录与反爬。

条目整个重写（重建条目的进程成为属主）。现在封闭模式下密钥读写全部走数据目录里的文件库，
启动守卫自检，`/state.startup` 报告 `prefs` / `secrets`。详见 AGENTS.md 启动流程一节。

## 不做

- **无人值守审批处置档**（上一版草案，见 `ROADMAP-0.8.76-ALT-unattended.md`）：它押在
  定时任务上，而定时任务的真实使用量是 0。保留草案，等有真实使用再启。
- 全量工具描述审计（被旗舰 D 覆盖）；体检周期化；教训逐条归因；新图表类型；
  Android / iOS Watch；crew 重写；其余既有否决维持。

## 风险

- **直通误触发**：唯一命中 + 阈值保守 + 首版只对样本 ≥ 2 的技能启用 + 面板可见 +
  设置开关。
- **合成的 useSkill 调用对**必须与真实调用形状一致（配对、id），否则被网关拒绝——
  harness 断言配对。
- **补丁改坏技能**：只走确认落地（不提供自动应用）；提出与采纳两次定点校验；旧版备份可回退。
- **精简工具的协议与缓存差异**：逃生口 + 自动回退 + 四条门控，不满足就保持关闭。
- **护栏误伤合理的多次查看**：只提醒不硬停；且旗舰 C 让"等待"不再需要查看。
- **度量基线被开发实例污染**：批 1 先完成分源，再取基线。
