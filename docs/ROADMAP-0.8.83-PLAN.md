## Track A — 常规四主题（14 件）

### ① 浏览器基础（旗舰：顺手的三件）

**1. 工具栏自定义（显示/隐藏 + 排序）**
- **现状依据**：`Toolbar.swift` 固定布局；没有 toolbar 偏好（S1）。
- **增量**：设置页新增“工具栏”列表：可选按钮（主页/书签/下载/AI/标签概览/阅读器/
  分享等）显示/隐藏 + 上下移动排序；`Toolbar` 从 `KeyboardShortcutStore` 同款
  UserDefaults 读顺序；默认布局逐字节不变；拖动排序用设置页列表的 move，不做
  原生 toolbar 拖拽（SwiftUI toolbar 拖拽在 macOS 上不稳定）。
- **验收**：桥 E2E（隐藏/排序后 `/diag/toolbar` 顺序一致）+ 快照；默认布局回归。

**2. 标签概览键盘导航**
- **现状依据**：`TabOverviewView` 只有鼠标点击（S2）。
- **增量**：方向键在瓦片间移动焦点（行/列）、回车切换、空格关闭、Esc 退出；
  分组胶囊可 Tab 聚焦；焦点环可见；与现有标签搜索/概览快捷键不冲突。
- **验收**：桥/键盘注入 E2E（方向键/回车/Esc）+ VoiceOver 标签；不改鼠标行为。

**3. 支付卡编辑/替换**
- **现状依据**：`PaymentCardStore` 只有 add/delete（S3）。
- **增量**：编辑 Label/持卡人/有效期；换卡号时重写同一 Keychain 条目（保留 id/
  createdAt）；不提供 CVV；删除仍二次确认。
- **验收**：桥 E2E（编辑后 id 不变、last4/有效期更新、旧卡号失效）+ 快照。

**4. 下载优先级可见**
- **现状依据**：`DownloadPanel` 右键已有 High/Normal/Low，但列表没有优先级标识。
- **增量**：行内优先级 badge；排队原因同时显示“等名额/等时段”；高优先级在
  名额释放时先放行（现有 `sortDownloadsByPriority` 已有排序，补 UI 与回泵顺序核对）。
- **验收**：桥 E2E（三档优先级同时排队 → 高优先级先开始）+ 快照。

### ② Agent 基础（旗舰：评估与门禁闭环）

**5. E34–E38 评估用例**
- **现状依据**：`agent-eval.py` CASES 止于 E31（S4）。
- **增量**：E34 缓存前缀稳定（两回合 system 稳定段一致）、E35 审批预览/上限、
  E36 修订 diff/撤销、E37 预算/转存、E38 错过补跑；全部假端点确定性，
  `--only E34,E35,E36,E37,E38` 可单跑。
- **验收**：全过；CI 只跑纯逻辑/桥契约，不跑真模型。

**6. 通知动作 E2E**
- **现状依据**：Retry/Ignore 只接线（S5）。
- **增量**：桥 `/notifications/simulate` 触发一条带 category 的任务失败通知；
  测试侧读取 category/userInfo，调用 `NotificationRouter` 的 action 处理；
  断言 Retry 重投、Ignore 只激活。
- **验收**：桥 E2E + 通知授权 skip 语义（无授权明确 skip，不假绿）。

**7. 任务链失败恢复 E2E**
- **现状依据**：链状态/Continue 已有，但没有“第二步失败→从第二步继续”的自动化。
- **增量**：假端点让 A 成功、B 失败；验证链状态标记、Continue 复用 A 输出、
  重试后整链完成；失败通知带动作。
- **验收**：桥 E2E（两步链失败→继续→成功）+ 快照。

**8. 发版门禁加固**
- **现状依据**：`firstWindowMs` 后台启动假失败；预算已改轮询但没有独立探针（S7）。
- **增量**：`tools/launch-hermetic.sh --activate`（启动后立即激活，供启动指标/
  190 使用）；`tests/budget-probe.py` 单窗口假端点（460→warning、920/stopLevel=2/
  无 B-DONE）；190 默认 fresh + activate；Release/Debug 结论分栏模板。
- **验收**：连续两次 190（fresh）启动 <2s、预算 5 项全过；探针可单独运行。

### ③ 融合（旗舰：跨设备实测）

**9. 同步冲突双设备 E2E**
- **现状依据**：冲突动作只有编译/桥字段，没有真实双设备（S6）。
- **增量**：本地 API + MySQL/Redis 起两个客户端（两个独立 data-dir），造同一条
  书签的不同修改 → 服务端 LWW 冲突 → 一端“采用本地”重推 → 两端一致；另一条
  “采用远端”确认；只测可逆域。
- **验收**：`tests/sync-conflict-e2e.py`（需 DB；无 DB 明确 skip）+ 日志留档。

**10. Remote 冲突动作 E2E**
- **现状依据**：手机同步健康页按钮已接线，但没有控制帧实测。
- **增量**：桥 `/remote/dispatch` 发 `syncConflict`（id + flag）→ Mac 调用
  `resolveConflict` → 回帧冲突列表减少；错误 id 返回 error。
- **验收**：桥 E2E + iOS 构建契约。

**11. 冲突解决审计**
- **现状依据**：动作后记录直接消失（S10）。
- **增量**：本地审计（时间/域/条目标签/选择本地或远端/结果/设备名），保留 100 条；
  设置页可查看/清空；`/sync/conflicts/audit` 桥只读。
- **验收**：桥 E2E + 快照；不记明文密码/卡号。

**12. iOS 账号安全契约测试**
- **现状依据**：恢复码/审计/设备吊销已接 API，但没有契约测试；改密按决策不做。
- **增量**：假服务端或本地 API 跑恢复码生成/审计读取/设备吊销的解码与错误分支；
  旧服务端 404 显示“升级服务端”而不是空白。
- **验收**：iOS 契约测试（模拟器构建 + 假端点）；改密入口继续不出现。

## 风险

- **工具栏自定义**：默认布局必须逐字节不变；排序持久化与多窗口一致。
- **支付卡编辑**：换卡号必须原子重写 Keychain，失败不能留下“旧卡号+新元数据”。
- **冲突双设备 E2E**：需要真实 MySQL/Redis 与两个 data-dir；本机无环境时明确 skip。
- **190 启动指标**：`--activate` 只修测试口径，不能掩盖真实启动回归。
- **生产部署**：本机验证不等于生产；迁移前备份，失败回滚路径写清。
