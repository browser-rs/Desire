# 语义索引 spike：英文句向量与阈值标定（v0.8.22 批一）

日期：2026-10-30。目的：决定"全库语义检索"的**英文侧**用什么模型、检索阈值定在哪。
中文侧沿用 0.7.1 的 bge-small-zh 验收集（13/15 vs BM25 8/15），本次只补英文与阈值。

## 模型可用性

`NLEmbedding.sentenceEmbedding(for:)`（macOS 系统框架，零额外体积）：

| 语言 | 可用 | 维度 |
|------|------|------|
| English | ✓ | 512 |
| Simplified Chinese | ✓ | 640 |
| Traditional Chinese / 日 / 韩 / 德 | ✗ | — |

英文与 bge-small-zh（512 维）维度相同，但**语义空间不同**——实现上仍按
「来源 × 语言」分片，查询只与同语言分片比较，绝不跨空间算余弦。

## 英文召回（tools/vector-spike/semantic-en-spike.swift）

语料：24 篇构造英文短文（技术/新闻/科学/生活各 6 篇）+ 23 条查询，其中 18 条
是**同义改写**（与原文几乎无字面重叠），5 条是普通主题词查询；对照基线 = 词重叠率。
判定门槛：recall@5 ≥ 0.75 且明显高于字面基线。

| 指标 | NL 句向量 | 字面词重叠基线 |
|------|----------|----------------|
| recall@1 | 0.652 | 0.435 |
| recall@5 | 0.913 | 0.478 |
| MRR | 0.750 | 0.449 |
| 同义改写 recall@1 | 12/18 | 6/18 |
| 主题词 recall@1 | 3/5 | 4/5 |

结论：**英文用 NL 句向量**。它在同义改写上明显优于字面（12/18 vs 6/18），
但主题词查询仍然字面更强（4/5 vs 3/5）——检索侧维持"字面优先、语义补位"，
语义不做唯一排序。

## 阈值标定

分数分布（英文语料，gold vs 非 gold）：gold 平均 0.407（min 0.060），
非 gold 平均 0.153（max 0.448）。

真实数据（书签）补充标定：

- 英文同义改写命中 0.52；无关查询最高 0.36 → **阈值 0.38**。
- 中文（bge，查询侧带官方指令前缀）：改写命中 0.431；无关 0.364；
  字面同题 0.72 → **阈值 0.40**。
- **导航型短标题是特例**："GitHub""Stack Overflow" 这类条目对无关英文查询
  也能到 0.48（与 gold 0.52 只差 0.04，阈值分不开）。处理：这类条目
  不进索引（`SemanticSnapshots.isSemanticallyRich`：有标签即收；中文 ≥ 6 字；
  英文 ≥ 4 个有效词）。用户本来就用字面搜索找它们，语义索引不收没有损失。

## 复现

```bash
swift tools/vector-spike/semantic-en-spike.swift
# 应用内用桥端点标定（minScore 仅诊断用）：
#   GET /search/semantic?q=…&minScore=0.3
```
