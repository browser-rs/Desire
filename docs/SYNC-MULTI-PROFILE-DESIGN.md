# 同步多档案设计稿（v0.8.17 项 7，设计稿先行）

> 现状：SyncEngine 只同步**活跃档案**的桶（各域游标全局一份，不区分档案）。
> 目标：每个档案独立同步自己的数据，互不掺杂。

## 方案对比

### A. domain 后缀（推荐）

- 域名带档案后缀：`bookmarks@<profileID>`（服务端 `sync_items.domain` 是
  透明字符串，**不解读**——现有通用表零迁移）。
- 服务端改动：仅 `DOMAINS` 白名单从精确匹配放宽为"基础名命中即可"
  （`bookmarks`、`bookmarks@xxx` 都放行）。一行解析逻辑，无迁移。
- 客户端改动：SyncStore 的域键改为 `\(domain.rawValue)@\(profileID)`——
  adapter/防抖/隔离/开关全部复用；游标按档案天然隔离（键不同）。
- 开关：设置页同步类目仍按基础域展示（开关作用于全部档案的同基础域）；
  不逐档案开关（v1 简化）。
- 登录态：全部档案共用同一账号与主密钥（档案是浏览器数据隔离，不是账号
  隔离——与本地档案语义一致）。

### B. payload 内嵌 profileID + 单域

- 域名不变，client_id 混入档案前缀（`<profileID>:<realID>`）。
- 优点：服务端零改动；缺点：HMAC client_id 层挤进档案信息后，LWW 冲突
  展示/清理逻辑全要拆前缀， tombstone/GC 语义被污染——**否决**。

### C. 每档案一个虚拟设备

- 用 device 维度区分档案。语义错误（同机两档案 ≠ 两设备），设备面板与
  GC 游标全被搅乱——**否决**。

## 落地拆分（若批准）

1. 服务端：DOMAINS 匹配放宽（前缀命中）+ api-sync-smoke 加
   `bookmarks@p2` 用例（一个下午）。
2. 客户端：SyncStore 域键拼后缀 + 档案切换时的游标隔离自检
   （切档案 → 游标键不同 → 全量对账一轮）+ 同步日志/设置页显示档案名
   （一个批次）。
3. 已知边界：同机双档案同时开窗共享一个 SyncStore 实例——域键带各自
   档案后缀后互不覆盖；脏标记按"基础域"合并防抖即可（推两个域各推各的）。

## 明确的边界

- 档案删除：本地档案删除时该档案的远端数据**不自动清**（账号级数据，
  误删不可逆；给设置页一条手动清理入口进 v2）。
- 未登录：多档案方案不改变登录语义（登录仍全局一份）。
