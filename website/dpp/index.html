Desire Page Protocol
让页面成为智能体的一等公民

DPP 是一个声明式页面协议：站点告诉智能体「我有什么数据、能做什么动作」， 智能体据此精确读取与操作页面——不再靠脆弱的猜测去猜选择器。

进入演示商店 npm 安装（@browser-rs/dpp-sdk） CDN（desire-sdk.js）

01三层接入，一分钟上线

按投入从低到高，三个层级随时可用、可以叠加（高层级覆盖低层级）：

L0
well-known 站点声明
在 /.well-known/desire.json 放一份 JSON：站点级页面地图、登录态指引。 不改一行业务代码。
L2
页面内联声明
页面脚本直接设置 window.__desireProtocolExposed = {…}（原生声明形态， 无需引外部 SDK）；噪音区在元素上标 data-dpp-ignore。
L3
SDK 一行接入
<script src="https://desire.mankong.icu/desire-sdk.js"></script> 或 npm i @browser-rs/dpp-sdk（UMD/ESM 双产物）；自动发现数据视图与动作，支持事件（order-placed 等）主动唤起智能体。

02声明什么：views · actions · events

一个典型的 L3 声明长这样（来自演示商店）：

desire.expose({
  views: {
    products: { item: ".card[data-sku]",
      fields: { title: ".name", price: {selector: ".price", type: "price"},
                sku: {selector: ".", attr: "data-sku"} } }
  },
  actions: {
    "add-to-cart": { params: {sku: {type: "string", required: true}},
                     run: [{click: ".card[data-sku='{sku}'] button.add"}],
                     effects: "persist" },
    checkout: { run: [{click: "#checkout-btn"}], effects: "outbound" }
  },
  events: { "order-placed": {watch: ".toast.order"} }
});
  • views —— 结构化数据视图：选择器 + 字段类型（price/number/url/date 自动转换），pageExtract("products") 一次读全，支持 paged / infinite 自动翻页。
  • actions —— 声明式动作：pageAction("add-to-cart", {sku})； effects: "outbound" 的动作（下单、提交）会先向用户请求批准，危险操作不静默。
  • events —— 事件唤起： watched 的 DOM 事件发生时（如订单落定），智能体被自动唤醒处理。
  • ignore —— 噪音区：广告位、推荐流标上 data-dpp-ignore，智能体视而不见。

03L3 SDK：一行脚本，全量能力

在任意页面引入：

<script defer src="https://desire.mankong.icu/desire-sdk.js"></script>

工程化项目也可走 npm（UMD 与 ESM 双产物）：

npm install @browser-rs/dpp-sdk
import { createDesireSDK } from "@browser-rs/dpp-sdk";
const desire = createDesireSDK({ global: window,
  postControl: (p) => window.webkit?.messageHandlers.desireProtocolControl?.postMessage(p),
  postEvent:   (p) => window.webkit?.messageHandlers.desireProtocolEvent?.postMessage(p) });
desire.expose({ /* 同 script 用法 */ });

SDK 提供类型化字段抽取、动作执行器、事件观察与自动化翻页；与 Desire 的信任分级 （站点声明 < 页面声明 < 用户显式指令）天然协同——声明只描述能力，执行永远经过用户的 访问等级与审批闸门。

隐私边界：声明与抽取全部在本机完成，页面数据不上传；跨源 iframe 的声明聚合与 定向提取在宿主侧实现，页面之间互相不可见。

04演示场：真实请求的活样本

desire.mankong.icu/demo/ 是一条 十二场景演示街，每个场景对应一类协议特性（数据是示例、下单写演示库，非真实交易）。入口示例：

  • 演示商店 ——「列出商品」→ pageExtract("products")；「去结算」→ outbound 动作先批准； 下单成功 → order-placed 事件自动唤起智能体
  • 资讯（paged） —— 「把 4 页文章都收集齐」→ 声明式自动翻页
  • 信息流（infinite + shadow DOM） —— 滚动加载 + >>> 跨 shadow 边界字段
  • 嵌入（跨源 iframe） —— 宿主聚合内嵌小组件的声明，动作路由进所属框架
  • IM / 论坛 / 预约 / 向导 / 审核 / 看板 / 商品 / 登录指引

商店页右下角的虚线框是 data-dpp-ignore 标注的噪音横幅——智能体会绕开它。

05第三方适配包：站点不接入也能用

很多站点不会主动接入。Desire 支持外挂 DPP 适配包：按 host 匹配的声明式 JSON （与 expose() 同一套协议格式），由第三方为热门站点编写——浏览器加载后 自动与页面合并（同名键站点声明优先、适配器补齐；动作照走审批链，纯 JSON 零代码）。

{
  "format": "desire/adapter-1",
  "name": "juejin",
  "hosts": ["juejin.cn", ".juejin.cn"],
  "pathPrefixes": ["/entry/", "/post/"],
  "protocolBody": { "views": { … }, "actions": [ … ] }   // 与 expose() 同格式
}
  • 现成包：掘金文章页（读文章/评论 + 点赞/评论动作）、掘金创作页（发沸点/写文章）、 V2EX 主题页（读主题/总结回复）——全部经真实页面核对，源在仓库 docs/dpp-adapters/
  • 安装：Desire 设置 › AI › DPP 协议 › 第三方适配 —— 粘 raw 链接即装 （https://raw.githubusercontent.com/browser-rs/Desire/main/docs/dpp-adapters/<包名>.json）， 或下载后文件导入；逐包启停，删了即失效
  • 写一份：选择器保守多候选、只声明核对过的动作、ignore 排噪音—— 守则见目录 README； 提 PR 进该目录即完成"上架"（raw 链接即刻可用）

06兼容性与边界

  • 非 Desire 浏览器完全无感：声明只是页面里的静态数据，不执行任何行为。
  • 同源与跨源 iframe 的声明聚合、定向抽取与逐框架动作路由均已支持； 宿主与审批卡会标注声明来源框架（见嵌入场景）。
  • 单页应用：路由变化后重新 expose() 即可，声明可随时更新（SDK 会通知宿主重解析）。
  • well-known 支持登录态指引（loginUrl 等），帮助智能体在需要时引导用户登录； 站点在 /.well-known/desire.json 放页面地图即可零改造接入。
  • shadow DOM：open shadow root 内的数据用 >>> 声明即可抽取。
