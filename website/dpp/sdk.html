DPP SDK 参考

L3 接入（desire/1）· SDK 版本 1.0 · 与 Desire 浏览器（及任何读取 window.__desireProtocolExposed 的宿主）协同

接入

<script defer src="https://desire.mankong.icu/desire-sdk.js"></script>
<script>
  desire.expose({
    protocol: "desire/1",
    page: { type: "catalog" },
    content: { main: ".product-grid", ignore: [".ad-slot"] },
    views: { products: { item: ".card", fields: { title: "h3", price: {selector: ".price", type: "price"} } } },
    signals: { ready: "[data-app-ready]" },
    actions: [ { name: "add-to-cart", run: [{ click: ".add-btn" }], effects: "persist" } ],
    events: { "order-placed": { watch: ".toast.order" } }
  });
</script>

SPA 路由变化时重新调用 expose() 即可——SDK 会通知 Desire 重新解析。 非 Desire 浏览器里 SDK 完全无副作用（只是往 window 挂了一个对象）。

npm / 打包器接入

npm install @browser-rs/dpp-sdk
import { createDesireSDK } from "@browser-rs/dpp-sdk";

const desire = createDesireSDK({
  global: window,
  postControl: (p) => window.webkit?.messageHandlers.desireProtocolControl?.postMessage(p),
  postEvent:   (p) => window.webkit?.messageHandlers.desireProtocolEvent?.postMessage(p),
});
desire.expose({ /* 同上 */ });

core 不依赖具体宿主（env 注入桥通道）；CDN 的 UMD 构建即上面 script 标签用的那份。

API

desire.expose(protocol)

desire.expose(protocol: object): void

声明本页协议。重复调用 = 更新（覆盖前一次声明并触发宿主重解析）。 声明对象即规范的页面级结构（§4）：page / content / signals / views / actions / events / context / profile。 动作对象形态（命名映射）与数组形态都接受；步骤里的对象 run 会自动序列化。

desire.emit(name, detail)

desire.emit(name: string, detail?: object): void

直接向宿主发射协议事件——比 events.watch 的 DOM 监听更精确（无防抖/时序问题）。 适合订单落定、消息到达等明确时点：

desire.emit("order-placed", { orderId: "A-1024", total: 128.5 });

事件会进入宿主的信任分级（§6）：页面自发事件是提示，不是指令。

desire.validate()

desire.validate(): { valid: boolean, warnings: string[], views: string[] }

开发期自检：检查 signals.ready 缺失、无视图、动作缺 name/run，以及 Profile 契约（规范 §5）——声明了 profile: "checkout" 就承诺提供 cart/orderSummary 视图与 place-order 动作，缺了会逐条列出。结果同时打印到 console。

desire.debug(on)

desire.debug(on?: boolean): void

开启/关闭 SDK 的 console 调试日志。

无 SDK 的等价形态

SDK 是可选的：L2 内联声明（设 window.__desireProtocolExposed = {…} 或插入 <script type="application/x-desire+json">）与 L0 well-known（站点级 /.well-known/desire.json：页面地图 + 登录态指引）不引任何脚本。三层可叠加， 页面级覆盖站点级。演示场每个页面底部都有「SDK 缺席降级」的静态声明块示范。

宿主侧行为（Desire 浏览器）

  • 解析时机——导航完成（didFinish）解析页面声明；SDK 的 expose 会主动通知重解析（SPA 场景）。
  • 跨源 iframe 聚合——子框架的声明按框架聚合；pageExtract/pageAction 按声明来源路由进所属框架执行，页面之间互相不可见。DevTools「DPP」页签的 Declaration frames 段亮出每个来源框架（跨源标红）。
  • 审批标注——动作声明自跨源框架时，审批卡上标注来源框架 host； effects: "outbound" / danger / 含 mcp 步骤的动作强制审批。
  • 事件——watch 命中或 emit 到达时，智能体被唤起处理（宿主做防抖/节流）。
  • 信任分级——站点声明 < 页面声明 < 用户显式指令；声明只描述能力， 执行永远经过访问等级与审批闸门。

上线检查单

  • 开发时在 console 跑 desire.validate()，清零 warnings。
  • signals.ready 指向数据真正就绪的标记（而不是 DOMContentLoaded）。
  • 噪音区（广告/推荐流）标 data-dpp-ignore 或写进 content.ignore。
  • 对外不可逆的动作（下单/发帖/支付）声明 effects: "outbound"——会强制审批，这是特性不是负担。
  • 有明确业务时点用 desire.emit()，不要让智能体猜 DOM 变化。
  • 想让智能体在任意页面认出你的站点？在 /.well-known/desire.json 放页面地图与登录指引。
